# Deploying KudiReady (≈15 minutes, free tiers)

You need: a GitHub account, a [Render](https://render.com) account and a [Vercel](https://vercel.com) account (both can sign in with GitHub).

## 1. Push to GitHub

```bash
cd kudiready
gh repo create kudiready --public --source=. --push      # or create the repo on github.com and:
# git remote add origin https://github.com/<you>/kudiready.git && git push -u origin main
```

Open the **Actions** tab — the CI workflow runs three jobs (API, Web, Docker). Wait for green.

## 2. API + database on Render

1. Render dashboard → **New → Blueprint** → select the `kudiready` repo. Render reads `render.yaml` and proposes `kudiready-db` (Postgres 16) and `kudiready-api` (Docker web service).
2. It asks for `CORS_ORIGINS` — enter `http://localhost:5173` for now (you'll update it in step 4).
3. **Apply**. First build takes ~5 minutes. Migrations run automatically on start.
4. Open `https://kudiready-api.onrender.com/healthz` (your exact URL is on the service page) → expect `{"status":"ok","database":true,...}`.
5. In the service's **Settings → Build & Deploy**, set **Auto-Deploy** to *After CI checks pass*.

## 3. Frontend on Vercel

1. Vercel → **Add New → Project** → import the repo.
2. **Root Directory**: `frontend`. Framework is detected as Vite.
3. **Environment Variables**: `VITE_API_URL` = your Render API URL (no trailing slash).
4. **Deploy**. Note the URL, e.g. `https://kudiready.vercel.app`.

## 4. Connect them

Render → `kudiready-api` → **Environment** → set `CORS_ORIGINS` to your Vercel URL (comma-separate if you add a custom domain) → **Save** (it redeploys).

## 5. Verify

- Visit the Vercel URL, create an account, set up a business, upload `sample-statement.csv`.
- Create a share link and open it in a private window.
- Put both public URLs into the README and the report.

## Notes

- **Cold starts**: Render's free web service sleeps after 15 minutes idle; the first request then takes ~30–50 s. Open `/healthz` a minute before your demo. The paid Starter plan removes this.
- **Free Postgres** on Render expires after 30 days — enough for assessment; upgrade or re-create afterwards.
- **Secrets**: `JWT_SECRET` is generated by Render; the API refuses to start in production with a weak or default secret.
